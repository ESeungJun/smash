#2026-11-01 앱에 API 키를 넣지 않고 PC의 Claude와 연동

  • 정한 것: Claude 기능은 사용자 PC에 로그인된 Claude Code CLI(claude -p)와 MCP 서버로만 쓴다.

  • 누가 정했나: 사용자 요구(프로젝트 메모리 "사용자는 앱에 Claude API 키를 넣지 말고 PC의 Claude와 연동하길 원함").

#2026-11-01 Tauri 대신 Electron

  • 정한 것: 앱 틀은 Electron, 화면은 프레임워크 없는 순수 JS.
  • 후보: Tauri / Electron.
  • 고른 이유: 개발 기기가 Intel Mac이고 Rust가 깔려 있지 않았다. Electron이면 앱 실행 파일을 ELECTRON_RUN_AS_NODE=1로 돌려 MCP 서버를 띄울 수 있어서 사용자가 Node를 따로 안 깔아도 된다.
  • 누가 정했나: 기록 없음.
  • 버린 시도: Tauri는 "다음 기회에"로 미뤘다.
  • 근거: 개발 글 2장("이 맥에 Rust가 안 깔려 있어서 Tauri는 다음 기회에"), 프로젝트 메모리, 로컬 히스토리 78849c0.

#2026-11-02 기본 규칙을 문서 폴더 기준으로, 미리보기를 폴더 트리로

  • 정한 것: 다운로드 파일을 문서/사진·이미지, 미디어, 자료, 개발리소스로 모으는 것을 기본 규칙으로 둔다. 미리보기는 목적지 기준 폴더 트리로 보여 주고 새 폴더·중복·이름 변경을 표시한다.
  • 후보: 다운로드 안에서 하위 폴더로 나누기(첫 판 FolderTidy) / 문서 폴더로 모으기.
  • 고른 이유: 정리 기준은 문서 폴더라는 사용자 요구. 파일이 어디로 가는지 모르면 정리 버튼을 못 누른다(목표 "맡겨도 불안하지 않게").
  • 누가 정했나: 사용자 요구(프로젝트 메모리 "정리 기준은 문서 폴더").
  • 버린 시도: 첫 판의 기본 규칙과 목록형 미리보기.
  • 근거: 로컬 히스토리 da18dde "등짝스매싱 v0.2: 문서 기준 규칙, 트리 미리보기, 자동 정리…", 개발 글 1장.

#2026-11-02 Claude 설정 위치를 전부 찾아 MCP 등록

  • 정한 것: claude mcp add로 기본 ~/.claude.json뿐 아니라 CLAUDE_CONFIG_DIR·Orca 프로필 위치까지 찾아 등록한다. Claude Desktop 설정은 .bak으로 백업한 뒤 고친다.
  • 후보: 기본 위치에만 등록 / 쓰는 위치를 모두 찾아 등록.
  • 고른 이유: 사용자의 Claude가 Orca 프로필(CLAUDE_CONFIG_DIR)로 돌아서 기본 위치에만 등록하면 안 보였다. 첫 판에는 claude mcp add 인자 순서 버그도 있었다(-e는 서버 이름 뒤에).
  • 누가 정했나: 기록 없음.
  • 버린 시도: 기본 위치에만 등록하던 첫 판.
  • 근거: 로컬 히스토리 da18dde("claude mcp add 인자 순서 버그를 고치고 모든 Claude 설정 위치에 등록한다"), 프로젝트 메모리.

#2026-11-02 빌드 이름은 영문 Smash로 고정, 화면 이름만 따로

  • 정한 것: electron-builder productName은 영문 Smash. 화면 이름은 build/lproj·app.setName·NSIS 바로가기로 준다. 설치본 확인은 30초 넘게 띄우고 크래시 리포트까지 본다.
  • 후보: 한글 이름 '스매시'를 빌드 이름으로 / 영문 빌드 이름 + 현지화 표시 이름.
  • 고른 이유: 이름을 한글로 바꾼 직후 설치한 앱이 8초쯤 뒤에 죽었다. 실행 파일은 Smash인데 Helper 앱이 '스매시 Helper'로 만들어져 Electron이 Helper를 못 찾았다. 처음에 7초 띄워 보고 고쳐진 줄 알았던 것이 확인 기준을 30초로 늘린 이유다.
  • 누가 정했나: 기록 없음.
  • 버린 시도: 한글 실행 파일 이름(f087732에서 실행 파일만 영문으로 바꿨으나 Helper 이름이 남아 있었음).
  • 근거: 로컬 히스토리 f087732, d7c46c0 "앱이 바로 죽던 문제 수정: 빌드 이름을 Smash로 통일", 개발 글 3장, README "개발" 절.

#2026-11-02 한글 파일 이름은 NFC로 맞춰 비교

  • 정한 것: 파일 이름과 규칙 단어, 건너뛰기 패턴을 모두 NFC로 바꿔 비교한다. 같은 일이 다시 안 생기게 테스트를 더했다.
  • 후보: 기록 없음.
  • 고른 이유: "스크린샷" 규칙이 실제 스크린샷 파일을 하나도 못 잡았다. macOS가 한글 파일 이름을 자모로 풀어(NFD) 돌려줘서 사용자가 입력한 완성형(NFC)과 비교가 안 맞았다.
  • 누가 정했나: 기록 없음.
  • 버린 시도: 없음.
  • 근거: 로컬 히스토리 e8a7401, 개발 글 3장, 테스트 "matchRule: macOS가 자모로 풀어 준(NFD) 한글 파일 이름도 단어로 잡는다".

#2026-11-02 정리하는 순간 등짝 스매시, 효과는 "찰싹!!" 한 번

  • 정한 것: 정리 버튼을 누르면 투명 전체화면 창에 손바닥이 나타나 내리치고(0.8초), 그 순간 정리한다. 글자는 "찰싹!!" 하나. 설정에서 끌 수 있다.
  • 후보: "등짝 스매시!" 글자 효과(f087732) / "딱!" 나타났다 "쾅!" 내리치는 두 단계(e8a7401) / "찰싹!!" 한 번(a0c71b7).
  • 고른 이유: 정리 앱은 많아서 한 번 더 누르고 싶게 만들고 싶었다. 두 단계는 해 보니 과했고, 등짝 맞는 소리는 "찰싹"이다.
  • 누가 정했나: 기록 없음.
  • 버린 시도: "등짝 스매시!" 글자, 딱·쾅 두 단계.
  • 근거: 로컬 히스토리 f087732, e8a7401, a0c71b7, 개발 글 4장.

#2026-11-02 효과가 끝난 뒤에 폴더 열기, 효과 창은 강제로 닫기

  • 정한 것: "내리치는 순간(hit)"과 "효과 창이 닫힌 순간(done)"을 따로 기다린다. 정리는 hit에, 폴더 열기는 done 뒤에. 효과 창은 늦어도 3초 안에 강제로 닫는다. 정리가 겹치면 효과를 차례로 돌린다.
  • 후보: 기록 없음.
  • 고른 이유: 정리할 폴더가 Finder에 이미 열려 있으면 효과보다 폴더 창이 먼저 튀어나왔다. 전에 띄운 효과 창이 덜 닫힌 채 남아 있으면 효과를 건너뛰고 바로 정리하고 있었다.
  • 누가 정했나: 기록 없음.
  • 버린 시도: 효과 창이 남아 있으면 효과 없이 정리하던 방식.
  • 근거: 로컬 히스토리 a0c71b7, 3f71d5e "정리가 겹치면 효과를 차례로 돌리고…", 개발 글 4장.
