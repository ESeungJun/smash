#정리하기 버튼 (등짝 스매시)

sequenceDiagram
  participant U as 사용자
  participant R as 렌더러 app.js
  participant M as main.js
  participant FX as 효과 창 smash.html
  participant O as organizer.js
  U->>R: 짝! 정리하기
  R->>M: invoke("apply", items)
  M->>M: smashQueue에 줄 세움 (겹치면 차례로)
  M->>FX: 투명 전체화면 창 띄움 (마우스 통과)
  Note over FX: 0.8초에 손바닥이 내리침
  M->>M: hit: 앱 창 흔들기
  M->>O: applyPlan(cfg, items)
  O-->>M: results, run (history.json에 기록)
  FX-->>M: 2초 뒤 창 닫힘 (늦어도 3초 안에 강제로 닫음)
  M->>M: done: 옮긴 자리들의 공통 상위 폴더 열기
  M-->>R: 결과
  • hit과 done을 따로 기다린다. 효과 창이 안 닫힌 채 남아도 정리는 1.5초 안에, 창은 3초 안에 끝난다(main.js smashEffect).

#자동 정리

sequenceDiagram
  participant FS as 파일 시스템
  participant W as watcher.js AutoTidy
  participant O as organizer.js
  participant M as main.js
  FS->>W: fs.watch 이벤트
  W->>W: 1.5초 디바운스
  W->>W: 수정 뒤 autoDelaySec(기본 10초)이 지났고 지난 확인 때와 크기가 같은 파일만 대상
  W->>O: scanTarget → applyPlan (사용자 규칙만, AI 제안 안 씀)
  O-->>W: 결과
  W->>M: onRun
  M->>M: 잔소리 배너 4.5초 (누르면 폴더 열기)
  Note over W: 10분마다 한 번 전체 훑기, 감시가 끊기면 30초 뒤 다시 걸기

#Claude에 자리 묻기

sequenceDiagram
  participant R as 렌더러
  participant M as main.js
  participant C as claude.js
  participant CLI as claude -p
  R->>M: ai:suggest(targetId, 규칙 없는 파일)
  M->>C: suggestPlacements
  C->>CLI: 이름·크기·날짜 + 폴더 목록 (stdin), 도구 끔, json-schema
  CLI-->>C: [{file, dest, reason}]
  C->>C: planFromMoves: 정리 대상 밖 목적지는 거부
  C-->>R: 계획 (미리보기에 "AI:" 이유와 함께 표시)

#핵심 파일

파일 설명
src/core/organizer.js scanTarget(계획), applyPlan(실행·안전장치), undoLast, planFromMoves(AI·MCP 계획 검증), folderTree. 한글 비교는 nfc()
src/core/config.js CATEGORIES(파일 종류 칩), defaultConfig(문서 폴더 기준 기본 규칙), normalize, writeJsonAtomic
src/core/watcher.js AutoTidy.sync가 자동 정리 켠 폴더만 감시
src/core/claude.js findClaudeCli, runCli, suggestPlacements, ruleFromText, claudeConfigLocations, registerClaudeCode, registerClaudeDesktop
src/mcp/server.js 줄 단위 JSON-RPC. initialize, tools/list, tools/call
src/main.js mcpLaunch, smashEffect, smashAndApply, tidiedFolder, showNag, IPC 핸들러(config:*, scan, apply, undo, ai:suggest, integration:* 등)
test/core.test.js SMASH_HOME을 임시 폴더로 두고 core·MCP·AutoTidy를 검증

#빌드·실행·배포

npm install
npm start          # 앱 실행
npm test           # node --test test/*.test.js
npm run mcp        # MCP 서버만 띄우기 (ELECTRON_RUN_AS_NODE=1)
npm run icons      # assets/*.svg → build/icon.png, 트레이 아이콘
npm run dist:mac   # dist/Smash-macOS-arm64.dmg, dist/Smash-macOS-x64.dmg
npm run dist:win   # dist/Smash-Windows-x64-Setup.exe (macOS에서도 빌드됨)
  • 빌드 productName은 영문 Smash로 둔다. 실행 파일과 Helper 앱 이름이 이걸 따라가는데, 둘이 어긋나면 "Unable to find helper app"으로 앱이 켜진 뒤 바로 죽는다. 화면 이름 Smash!는 build/lproj와 app.setName이 맡는다.
  • 설치본을 확인할 때는 30초 넘게 띄워 두고 크래시 리포트까지 본다.
  • 배포: dist/의 dmg 두 개와 exe를 GitHub 릴리스에 올린다. 파일 이름에 버전을 넣지 않아 README의 releases/latest/download/ 링크가 늘 최신을 가리킨다.
  • 깃 흐름(git flow, 도구 없이 수동): main은 릴리스만, develop이 기본 작업 브랜치, 기능은 feature/*, 릴리스는 release/x.y.z에서 버전을 올려 main에 합치고 vX.Y.Z 태그. 개발 중에는 버전을 올리지 않는다.
